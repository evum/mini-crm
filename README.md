# mini-crm

Мини CRM.

## Фронтенд

React + TypeScript + Vite, Tailwind CSS и shadcn/ui. Запросы и состояние
авторизации управляются через TanStack Query (`QueryClientProvider`, `useQuery`,
`useMutation`). Экран входа использует Supabase Auth (email и пароль),
восстанавливает сессию после перезагрузки и позволяет выйти из аккаунта.
После входа профиль загружается через `get_current_profile`: исполнитель видит
«Мои задачи», постановщик — «Объекты». При отсутствии активного профиля
показывается отказ в доступе с возможностью выхода и повторной загрузки.

У исполнителя рядом с «Моими задачами» доступна вкладка «Мои объекты»
(`#/objects`). В ней отображаются только объекты с назначенными ему задачами;
счётчики учитывают только его задачи. Фильтрацию обеспечивает RLS в базе.
Регистрации в интерфейсе нет. Открытую регистрацию нужно отключить отдельно
в настройках Supabase Auth.

### Запуск

1. Выполните `npm install`.
2. Скопируйте `.env.example` в `.env.local` и укажите URL проекта и
   **publishable key** из Supabase. Если `.env.local` уже настроен, сохраните его.
3. Выполните `npm run dev` и откройте адрес из терминала.

Переменные `VITE_*` доступны браузеру: не помещайте туда secret key,
`service_role`, пароль базы или другие секреты. Файлы `.env.local` исключены из Git.
Изменение переменных окружения требует перезапуска dev-сервера.

Проверка типов и production-сборка: `npm run build`. Результат — каталог `dist`.
Предпросмотр сборки: `npm run preview`.

Экран входа и используемые им компоненты shadcn/ui находятся в
`src/components/login`, «Мои задачи» и карточка задачи — в `src/components/tasks`,
«Объекты» — в `src/components/objects`. Общие элементы рабочего пространства —
в `src/components/workspace`. `src/App.tsx` проверяет сессию и профиль и выбирает
экран по роли. Настройки shadcn/ui — в
`components.json`. Тема и Tailwind подключены в `src/styles.css`,
алиас `@/` указывает на `src/`. Добавление компонентов:
`npx shadcn@latest add <component>`.

Сессия синхронизируется с событиями Supabase Auth. При выходе или смене
пользователя кэш прикладных запросов очищается. Автоматические повторы
запросов входа отключены. Пароли и кэш запросов не сохраняются отдельно на диск;
сохранением сессии управляет Supabase Auth.

Списки используют `list_my_tasks` и `list_objects`, поиск и серверную пагинацию
по 12 записей. У задач есть фильтр статусов, у объектов — счётчики задач и доля
принятых работ. Есть состояния загрузки, ошибки с повтором и пустого результата.
Карточка объекта показывает название, адрес, счётчики и список доступных задач
с поиском, фильтром статусов и пагинацией. Карточка задачи показывает описание,
статус, объект, исполнителя, автора, дату создания и историю статусов с комментариями.
История также поддерживает пагинацию.

Ссылки карточек: `#/objects/<uuid>` и `#/tasks/<uuid>`. Можно открывать их напрямую,
перезагружать страницу и пользоваться кнопками браузера «Назад»/«Вперёд».
Неверные ссылки показывают сообщение об отсутствующей странице; недоступные
данные — ошибку без раскрытия содержимого. Данные читаются через существующие
`get_object_details`, `list_tasks`, `get_task_details` и `list_task_history`.
В карточке задачи доступны разрешённые сервером переходы статусов. При возврате
на доработку обязателен непустой комментарий; для остальных действий он
необязателен. Запись выполняется через `change_task_status` с ожидаемым текущим
статусом. Во время запроса кнопки блокируются, автоматические повторы отключены.
После изменения перечитываются карточка, история, списки задач и счётчики объектов.
Конфликты статуса и отказы в доступе обрабатываются отдельно. Управление объектами
пока не реализовано.
Доступ к данным независимо проверяется существующими RLS и RPC на стороне базы.
Типы схемы Supabase сохранены в `src/lib/database.types.ts`.

Все обращения к Supabase вынесены в `src/api`: `client.ts` создаёт клиент,
`auth.ts` управляет сессией, входом, выходом и подпиской на события авторизации,
`profiles.ts` загружает и проверяет профиль, `objects.ts` и `tasks.ts` читают
прикладные данные. API-функции возвращают данные и выбрасывают ошибки;
TanStack Query в хуках и компонентах управляет кэшем и состоянием запросов.
Для чтения данных передаётся `AbortSignal`, отменяющий сетевой запрос.

Для проверки входа используйте пользователя, вручную созданного в Supabase Auth.
